# CSG - Руководство по стилю кода

> **Code Style Guide** — стандарт кодирования для проектов.

> 🇬🇧 **English version:** [CSG.md](CSG.md)

---

## 📁 Структура проекта
- Весь код должен находиться внутри директории `src/` или `app/`.
- В корне проекта не должно быть никакого кода.

---

## 📝 Документация и комментарии
- Все комментарии к коду и документация должны быть написаны на **английском языке**.
- Каждый **исполняемый скрипт** (например, Python, Bash) должен начинаться с **шебанга** (`#!/usr/bin/env ...`), за которым следует многострочный комментарий с описанием проекта или модуля.
- **Шебанг не требуется** для:
  - Модулей Python (например, файлов, предназначенных для импорта, а не для прямого запуска).
  - Крайтов (crates) Rust.
  - Исходных файлов C/C++.
  - Любых языков, в которых не используются шебанги.

---

## 🐍 Соглашения об именовании
- **Переменные, функции, директории:** `snake_case`
  Пример: `get_data()`, `user_id`
- **Классы:** `CapitalizedCamelCase`
  Пример: `CatDatabase`

---

## ⚠️ Обработка ошибок
- Код **никогда не должен падать молча**.
- Критические ошибки должны перехватываться с помощью:
  - `try/except` (Python)
  - Типов `Result` (Rust)
  - Эквивалентных механизмов в других языках
- Всегда выводите **понятное и удобное для пользователя сообщение об ошибке**.

---

## 🧠 Аннотации типов
- Аннотации типов должны быть указаны для **всех сигнатур функций**.
- Это улучшает читаемость кода и делает возможным статический анализ.

---

## 📦 Сообщения коммитов
- Должны соответствовать стандарту **Conventional Commits**:
  - `feat:`, `fix:`, `docs:`, `style:`, `refactor:`, `test:`, `chore:`
- Должны быть написаны исключительно на **английском языке**.
